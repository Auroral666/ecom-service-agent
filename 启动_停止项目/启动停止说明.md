# 一键启动与停止

双击项目 `启动_停止项目` 文件夹内的 **启动项目.cmd**，等待出现“启动完成”。脚本依次检查运行环境、准备配置需要的本地向量服务、启动后端、启动前端，再检查前后端连接；不会自动安装依赖或修改业务配置。

启动成功后访问：

- 前端入口：http://127.0.0.1:5173
- 客户页面：http://127.0.0.1:5173/chat
- 客服页面：http://127.0.0.1:5173/support
- 后端：http://127.0.0.1:18080
- 接口文档：http://127.0.0.1:18080/docs
- 后端健康检查：http://127.0.0.1:18080/api/health
- 本地向量服务（配置启用时）：http://127.0.0.1:18181/v1

浏览器访问前端 5173，前端将 `/api` 请求转发至后端 18080。后端使用 `-X utf8`、`PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8` 启动。

双击 **停止项目.cmd**，依次停止本项目的前端、后端、本地向量服务及相关子进程。账号、会话、数据库和其他项目文件会保留。关闭启动窗口不会停止后台服务。

重复启动会复用已登记并通过健康检查的项目服务；重复停止会提示“未运行”。遇到其他程序占用端口会报错，脚本不会按端口直接结束未知进程。

运行记录位于 `.runtime/services.json`，日志位于 `.runtime/logs/`。进程 ID、创建时间和启动命令会一起校验，以避免进程 ID 被复用后误停其他程序；端口归属检查也支持 Windows 虚拟环境 Python 创建的服务子进程。不要在服务运行期间手动修改运行记录。

## 环境与故障排查

脚本优先使用项目 `.venv` 中的 Python，并检查现有 Node.js 安装。需要更换环境时，可提前设置以下环境变量为可执行文件的完整路径：

- `ECOM_PYTHON`：后端 Python，默认使用项目 `.venv`，找不到时尝试系统 Python。
- `ECOM_NODE`：Node.js，默认尝试现有安装和系统 Node.js。
- `ECOM_EMBEDDING_PYTHON`：本地向量服务 Python，默认使用 `rag-env` 环境。

如果提示前端依赖不存在，先在 `frontend` 目录执行 `npm install`；如果 Python 依赖检查失败，先在后端 Python 环境安装 `requirements.txt` 中的依赖。如果服务启动失败，按提示查看对应 `*.err.log`。本地模型第一次加载可能需要等待，向量服务等待上限为 120 秒。

脚本使用项目所在位置作为工作目录，可处理中文和空格路径；内部端口与现有 Vite 代理保持一致。复制项目到其他电脑时，需重新准备运行环境、`.env` 和本地模型，不能只复制两个 CMD 文件。

命令行聊天可使用后端 Python 执行 `main.py`，与 Web 服务控制脚本用途不同。

在项目根目录命令行验证时，可使用 `.\启动_停止项目\启动项目.cmd --no-pause` 或 `.\启动_停止项目\停止项目.cmd --no-pause`，跳过完成后的按键等待；也可以运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/project-services.ps1 -Action Status` 查看状态。两个 CMD 会从自身位置定位上一级项目根目录，无需事先切换工作目录。
